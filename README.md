# Discord-бот: роли, позор и AI

Модульный бот на `discord.py`. Все функции реализованы как отдельные коги
(`cogs/*.py`) и загружаются автоматически при старте — чтобы добавить новую
функцию, достаточно положить новый файл в `cogs/`.

## Структура проекта

```
discord_bot/
├── bot.py                 # точка входа, автозагрузка когов
├── config.py               # чтение .env
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
├── .env.example
├── database/
│   └── db.py                # SQLite (aiosqlite), схема БД
├── cogs/
│   ├── roles.py              # /role — база ролей, выдача, топы
│   ├── shame.py               # /shame — позор + голосования
│   └── ai_chat.py             # /ask — ChatGPT / Claude / DeepSeek
└── data/                    # тут будет лежать bot.db (создаётся сама)
```

## Что умеет бот

### `/role` — роли
- `/role create name description criteria color stackable` — создаёт роль в Discord и заносит в базу (описание + за что выдаётся).
- `/role list` — список всех зарегистрированных ролей.
- `/role info role` — описание роли + сколько человек её носит.
- `/role give member role reason` — выдать роль участнику (с логированием).
- `/role top role limit` — топ по роли: если роль **stackable** — рейтинг по числу выдач (как очки), если нет — по дате получения (кто раньше всех получил).
- `/role edit role name description criteria color` — изменить роль (с учётом прав ниже).
- `/role delete role delete_from_discord` — удалить из базы (и, опционально, с сервера) — с учётом прав ниже.
- `/role setup admin_role trusted_role edit_window_hours` — настроить, кто и как долго может редактировать/удалять роли (только для администраторов Discord).

**Права на редактирование/удаление ролей:**
- роль **«админ»** (или та, что указана в `/role setup admin_role:...`) может редактировать/удалять любую роль всегда;
- роль **«бро &lt;3»** (или указанная в `/role setup trusted_role:...`) может редактировать/удалять роль, **только если** та создана через `/role create` и ещё не истекло «окно редактирования» (по умолчанию 24 ч, настраивается через `/role setup edit_window_hours:...`);
- роли, зарегистрированные в базе **до** появления этой функции, а также роли с истёкшим окном — редактировать/удалять может только «админ».

По умолчанию роли ищутся по названию «админ» и «бро &lt;3» (регистр не важен); это можно поменять в `.env` (`ROLE_ADMIN_NAME`, `ROLE_TRUSTED_NAME`) или командой `/role setup`, указав конкретные роли сервера напрямую — так надёжнее, если роль потом переименуют.

### `/shame` — позор
- `/shame give member duration_hours reason` — выдать позор напрямую (модератор).
- `/shame remove member reason` — снять позор напрямую, с забавной подписью.
- `/shame status member` — сколько осталось времени.
- `/shame list` — кто сейчас в позоре.
- `/shame vote_give member reason shame_duration_hours` — запускает голосование ✅/❌ за выдачу позора.
- `/shame vote_remove member reason` — голосование за досрочное снятие позора «за заслуги».
- `/shame setup role vote_threshold vote_window_hours log_channel` — настройка: роль позора (создастся сама, если не указать), порог голосов, длительность голосования, канал для объявлений.

Фоновые задачи (проверка раз в минуту) сами:
- снимают позор по истечении срока и публикуют случайную шутливую фразу вроде *«Был отмыт от позора, но всё равно остался дырявым»*;
- подводят итоги голосований по истечении времени и применяют/отклоняют решение.

### `/ask` — обращение к AI
`/ask provider:ChatGPT|Claude|DeepSeek prompt:...` — отправляет вопрос выбранной модели и возвращает ответ. Нужен хотя бы один из ключей `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `DEEPSEEK_API_KEY` в `.env`.

## Шаг 1. Создание приложения бота в Discord

1. Зайдите на https://discord.com/developers/applications → **New Application**.
2. Слева откройте **Bot** → **Reset Token** → скопируйте токен (это `DISCORD_TOKEN`).
3. Там же включите (обязательно, иначе бот не увидит участников/сообщения):
   - **Server Members Intent**
   - **Message Content Intent**
4. Слева откройте **OAuth2 → URL Generator**:
   - Scopes: `bot`, `applications.commands`
   - Bot Permissions: как минимум `Manage Roles`, `Send Messages`, `Embed Links`, `Add Reactions`, `Read Message History`, `View Channels`.
5. Скопируйте сгенерированную ссылку, откройте в браузере и пригласите бота на сервер.

   ⚠️ Роль бота в списке ролей сервера должна быть **выше** ролей, которые он будет выдавать (включая роль «Позор»), иначе Discord не даст ему их выдавать/снимать.

## Шаг 2. Настройка окружения

На сервере (в пустующем сервере, о котором вы писали):

```bash
git clone <ваш-репозиторий-или-просто-скопируйте-папку> discord_bot
cd discord_bot
cp .env.example .env
nano .env   # или любой редактор
```

Заполните как минимум:
```
DISCORD_TOKEN=ваш_токен
GUILD_ID=id_вашего_сервера   # необязательно, но команды появятся мгновенно
```

Как узнать `GUILD_ID`: в Discord включите режим разработчика (Настройки → Расширенные → Режим разработчика), затем ПКМ по серверу → «Копировать ID».

Ключи для AI (по желанию, только для нужных провайдеров):
```
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
DEEPSEEK_API_KEY=sk-...
```

## Шаг 3. Запуск в Docker

Требуется установленный Docker и Docker Compose (`docker compose version` для проверки). Если их нет:

```bash
curl -fsSL https://get.docker.com | sh
sudo apt install -y docker-compose-plugin   # для Debian/Ubuntu
```

Запуск бота:

```bash
docker compose up -d --build
```

Проверить логи:

```bash
docker compose logs -f discord-bot
```

Остановить:

```bash
docker compose down
```

Обновить после изменения кода:

```bash
git pull   # или обновите файлы вручную
docker compose up -d --build
```

База данных SQLite хранится в `./data/bot.db` на хосте (примонтирована как volume), поэтому переживает пересборку и перезапуск контейнера.

## Шаг 4. Первая настройка на сервере

После того как бот запущен и в сети:

1. `/shame setup vote_threshold:3 vote_window_hours:24` — настроит систему позора (роль создастся автоматически, если не указать свою).
2. `/role create name:Ветеран description:"Старожил сервера" criteria:"Более 1 года на сервере"` — создайте первую роль.

## Как добавить новую функцию

1. Создайте файл `cogs/моя_фича.py`.
2. Опишите класс-ког (`commands.Cog` или `commands.GroupCog`, если нужна группа `/команда подкоманда`).
3. В конце файла обязательно добавьте:
   ```python
   async def setup(bot):
       await bot.add_cog(МойКог(bot))
   ```
4. Если нужны новые таблицы — допишите их в `SCHEMA` в `database/db.py` (через `CREATE TABLE IF NOT EXISTS`, это безопасно для существующей базы).
5. Перезапустите бота — файл подхватится автоматически, ничего в `bot.py` менять не нужно.

## Частые проблемы

- **Слэш-команды не появляются** — без `GUILD_ID` глобальная синхронизация может занимать до часа. Для разработки указывайте `GUILD_ID` — команды обновятся мгновенно.
- **Бот не может выдать роль** — проверьте, что роль бота в иерархии ролей сервера выше выдаваемой роли.
- **`Server Members Intent` не включён** — без него бот не увидит участников сервера, и часть команд (например, `/role top`) будет работать некорректно.
- **`/ask` возвращает ошибку про ключ** — убедитесь, что соответствующий `*_API_KEY` указан в `.env` и контейнер перезапущен (`docker compose up -d --build`).
